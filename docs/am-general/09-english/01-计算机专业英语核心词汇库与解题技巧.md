## 一、 核心考纲与题型规律

上午试卷第 71 ~ 75 题固定为一篇 **300 ~ 400 词的计算机专业英文科技短文**，挖空 5 处作为单选题。

1. **面向对象与设计模式**（类图交互、封装继承多态、松耦合设计模式意图）；

## 三、 软考专业英语三大解题绝技

1. **“软考第一美德优先选”原则**：
   - 架构目标选项中出现 `loose coupling`（松散耦合）、`high cohesion`（高内聚）、`readability`（可读性）、`maintainability`（可维护性）、`reliability`（可靠性），极大概率是正确选项！
2. **“同位语与定语从句”直接定义定位法**：
   - 英文科技文中，生词或挖空后方紧跟的从句（`which...`、`that...`）或破折号、括号说明，往往就是该术语的标准定义，直接反向映射中文概念即可。
3. **“逻辑衔接词”正反验证法**：
   - 遇到 `in contrast to`、`however`、`whereas`，挖空前后词义必定对立相反；
   - 遇到 `and`、`furthermore`、`similarly`，挖空前后词义必定同向并列。

## 四、 典型真题溯源与逐项排错解析 (Distractor Analysis)

### 【真题精选 1】（考查微服务架构与松散耦合 · 2024上-机考回忆-Q71~72）
**Passage**：
Microservices are an architectural approach where a single application is composed of many small, independently deployable services. In contrast to traditional monolithic systems where all components are tightly (71), microservices focus on building modular components that communicate via lightweight APIs. 

This architectural style allows engineering teams to deploy updates independently, which significantly improves developer productivity and system (72). If one component fails, the entire application will not crash.

(71) A. isolated      B. coupled     C. protected   D. documented  
(72) A. vulnerability B. overhead    C. reliability D. delay  

- **【正确答案】**：**(71) B  (72) C**
- **【核心切入点】**：第 71 题考查传统单体系统的缺点是“紧密耦合 (tightly coupled)”；第 72 题单个服务故障不影响全局，提升的是系统“可靠性 (reliability)”。

#### 逐项排错剖析 (Distractor Analysis)
- **第 (71) 题排错**：
  - 题干指出“In contrast to traditional monolithic systems where all components are tightly (71)”（与所有组件紧密____的传统单体架构形成对比）；
  - **选项 B (coupled 耦合) 正确**：`tightly coupled`（紧密耦合）是软件体系结构对单体系统的经典定义。
  - **选项 A (isolated 隔离) 错误**：微服务才是组件隔离，单体架构缺乏隔离。
  - **选项 C (protected 保护) 与 D (documented 撰写文档) 错误**：不符合语境修饰。
- **第 (72) 题排错**：
  - 后句解释“If one component fails, the entire application will not crash”（一个组件故障应用不崩溃），这显著提升了系统韧性与可靠性。
  - **选项 C (reliability 可靠性) 正确**：软考第一美德词，正面评价指标。
  - **选项 A (vulnerability 脆弱性/漏洞) 错误**：负面词汇。
  - **选项 B (overhead 开销) 与 D (delay 延迟) 错误**：微服务由于网络 RPC 实际上增加了网络开销与延迟，绝非“significantly improves”的正向收益。

### 【真题精选 2】（考查面向对象三大核心特征英文表达 · 2024下-机考回忆-Q71~72）
**Passage**：
Object-oriented programming (OOP) is a programming paradigm based on the concept of objects, which can contain data and code. A key feature of OOP is (71), which enables a new class to acquire properties and methods from an existing class, promoting code reuse. Another fundamental concept is (72), which allows methods to take different forms based on the actual object that executes them at runtime.

(71) A. encapsulation  B. inheritance  C. abstraction  D. recursion  
(72) A. polymorphism   B. overloading  C. duplication  D. serialization  

- **【正确答案】**：**(71) B  (72) A**
- **【核心切入点】**：第 71 题“从现有类获取属性和方法以实现代码复用”即继承；第 72 题“运行时同一方法产生不同形式”即多态。

#### 逐项排错剖析 (Distractor Analysis)
- **第 (71) 题排错**：
  - 题干后置定语从句明确给出定义：“which enables a new class to acquire properties and methods from an existing class”（使新类能够从现有类中获取属性和方法）；
  - **选项 B (inheritance 继承) 正确**：继承机制的核心目的就是代码复用与类型层次演化。
  - **选项 A (encapsulation 封装) 错误**：封装是将数据和行为打包并隐藏细节。
  - **选项 C (abstraction 抽象) 错误**：抽象是提取共性形成概念模板。
  - **选项 D (recursion 递归) 错误**：算法递归调用，与面向对象特征无关。
- **第 (72) 题排错**：
  - 题干后置从句给出定义：“which allows methods to take different forms based on the actual object that executes them at runtime”（允许方法在运行时根据执行它的实际对象呈现不同形式）；
  - **选项 A (polymorphism 多态) 正确**：多态（Polymorphism）强调同一操作作用于不同运行时对象产生不同执行效果。
  - **选项 B (overloading 重载) 错误**：重载是编译期多态（静态绑定），并非根据运行时实际对象分发。
  - **选项 C (duplication 代码重复) 错误**：负向代码坏味道。
  - **选项 D (serialization 序列化) 错误**：对象持久化字节流机制。
