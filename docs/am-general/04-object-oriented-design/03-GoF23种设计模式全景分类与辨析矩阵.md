## 一、 核心考纲与概念辨析

### 1. 23 种设计模式全景矩阵（按目的与范围分类）

GoF（Gang of Four）设计模式根据**目的（创建/结构/行为）**与**范围（类模式/对象模式）**二维划分如下：

| 分类（按目的） | 模式名称 | 英文名称 | 范围（类/对象） | 核心意图与设计动机 | 经典应用场景 / 现实隐喻 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **创建型模式**<br>(Creational)<br>*关注对象的创建机制，将系统的对象创建与表示分离* | **工厂方法** | Factory Method | **类模式** | 定义一个创建对象的接口，让子类决定实例化哪一个类 | 日志记录器、不同数据库驱动连接 |
| | **抽象工厂** | Abstract Factory | 对象模式 | 提供一个创建**一系列相关或相互依赖对象族**的接口，而无需指定具体类 | 跨平台 UI 控件库（Windows/Mac 按钮与文本框族） |
| | **单例模式** | Singleton | 对象模式 | 保证一个类仅有一个实例，并提供一个访问它的全局访问点 | 线程池、数据库连接池、全局配置中心 |
| | **建造者模式** | Builder | 对象模式 | 将一个复杂对象的构建过程与其表示分离，使同样的构建过程可以创建不同的表示 | 肯德基组装汉堡套餐、组装不同配置的电脑 |
| | **原型模式** | Prototype | 对象模式 | 用原型实例指定创建对象的种类，并且通过**克隆（深拷贝/浅拷贝）**这些原型创建新对象 | 复杂大对象的快速复制（如 `Object.clone()`） |
| **结构型模式**<br>(Structural)<br>*关注类和对象的组合，通过继承或组合获得更大结构* | **适配器模式** | Adapter | **类/对象** | 将一个类的接口转换成客户希望的另外一个接口，解决接口不兼容问题 | 电源插头转接头、JDBC-ODBC 桥 |
| | **桥接模式** | Bridge | 对象模式 | 将**抽象部分与它的实现部分分离**，使它们都可以独立地变化（解耦多维度变化） | 毛笔与颜色分离、图形与操作系统渲染分离 |
| | **组合模式** | Composite | 对象模式 | 将对象组合成**树形结构**以表示“部分-整体”的层次结构，使用户对单个对象和组合对象的使用具有一致性 | 文件与文件夹目录树、公司组织架构 |
| | **装饰器模式** | Decorator | 对象模式 | **动态地给一个对象添加额外的职责**；比生成子类更为灵活 | Java I/O 流（`BufferedInputStream` 包装 `FileInputStream`） |
| | **外观/门面模式**| Facade | 对象模式 | 为子系统中的一组接口提供一个一致的界面，定义一个高层接口使得子系统更容易使用 | 医院接待处一站式挂号缴费、智能家居一键离家模式 |
| | **享元模式** | Flyweight | 对象模式 | 运用**共享技术**有效地支持大量细粒度对象的复用，区分内部状态与外部状态 | 围棋棋盘上的黑白棋子、文本编辑器字符图元 |
| | **代理模式** | Proxy | 对象模式 | 为其他对象提供一种代理以控制对这个对象的访问 | 远程代理、虚拟代理（延迟加载大图）、安全代理 |
| **行为型模式**<br>(Behavioral)<br>*关注对象之间的职责分配与算法控制流* | **责任链模式** | Chain of Responsibility | 对象模式 | 使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系，沿链传递请求 | 请假审批工作流、异常捕获链、过滤器链 |
| | **命令模式** | Command | 对象模式 | 将请求封装为一个对象，从而可用不同的请求对客户进行参数化；支持请求排队、撤销（Undo）与重做 | 遥控器按钮、文本编辑器撤销与重做操作 |
| | **解释器模式** | Interpreter | **类模式** | 给定一个语言，定义它的文法的一种表示，并定义一个解释器处理该文法 | 正则表达式解析器、SQL 解析器、算术表达式求解 |
| | **迭代器模式** | Iterator | 对象模式 | 提供一种方法顺序访问一个聚合对象中各个元素，而又不需要暴露该对象的内部表示 | Java `Iterator` 遍历 List/Set |
| | **中介者模式** | Mediator | 对象模式 | 用一个中介对象来封装一系列的对象交互，使各对象不需要显式地相互引用，松散耦合 | 机场空中交通管制塔、聊天室服务器、MVC 中的 Controller |
| | **备忘录模式** | Memento | 对象模式 | 在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态以便以后恢复 | 游戏存档读档、文档历史撤销快照 |
| | **观察者模式** | Observer | 对象模式 | 定义对象间的一种一对多的依赖关系，当一个对象的状态发生改变时，所有依赖于它的对象都得到通知并被自动更新 | 微信公众号订阅发布、事件监听机制 (Listener) |
| | **状态模式** | State | 对象模式 | 允许一个对象在其内部状态改变时改变它的行为，对象看起来似乎修改了它的类 | 自动售货机（无币/有币/售罄状态）、订单状态机流转 |
| | **策略模式** | Strategy | 对象模式 | 定义一系列算法，把它们一个个封装起来，并且使它们可以相互替换；算法独立于使用它的客户而变化 | 商场打折促销算法（打八折/满减/原价）、导航路线规划 |
| | **模板方法模式**| Template Method | **类模式** | 定义一个操作中的算法骨架，而将一些步骤延迟到子类中；子类可不改变算法结构而重定义特定步骤 | 泡茶/冲咖啡的标准流水线（烧水、冲泡、倒杯、加料） |
| | **访问者模式** | Visitor | 对象模式 | 表示一个作用于某对象结构中的各元素的操作；可以在不改变各元素的类的前提下定义作用于这些元素的新操作 | 编译器语法树检查、不同角色（医生/药剂师）看病历单 |

### 2. 类模式 vs 对象模式权威辨析（必考绝密题眼）

> [!IMPORTANT]
> 23 种设计模式中，**类模式仅有 4 种**，其余 19 种全部为**对象模式**：
> - **类创建型**：**工厂方法 (Factory Method)**
> - **类结构型**：**类适配器 (Class Adapter)**（通过多重继承实现）
> - **类行为型**：**解释器 (Interpreter)**、**模板方法 (Template Method)**
> 
> **记忆口诀**：**“解模工适”**（解释器、模板方法、工厂方法、适配器）为类模式！

---

### 3. 高频混淆模式对决与速判准则

1. **策略模式 (Strategy) vs 状态模式 (State)**：
   - **策略模式**：环境类持有算法接口，通常由**客户端显式指定**选择哪一种策略；各个策略算法之间是平等的、独立的、互斥的。
   - **状态模式**：状态的流转是**内部自动触发**的（状态自身决定下一状态）；客户端通常不需要关心内部具体状态的变化。
2. **装饰器模式 (Decorator) vs 代理模式 (Proxy)**：
   - **装饰器模式**：重点在**功能增强**（透明地添加职责）；装饰者与被装饰者通常由外部动态传入组合。
   - **代理模式**：重点在**访问控制**（权限验证、延迟加载、日志监控）；代理类通常自身直接管理目标对象的生命周期。
3. **工厂方法 (Factory Method) vs 抽象工厂 (Abstract Factory)**：
   - **工厂方法**：一个工厂等级结构对应一个产品等级结构（生产**单一产品**，如只生产汽车）。
   - **抽象工厂**：一个工厂等级结构对应多个产品等级结构（生产**产品族**，如同时生产配套的汽车底盘、轮胎和发动机）。

## 二、 命题题眼与陷阱防御

> [!CAUTION]
> ### 🚨 常见命题陷阱盘点
> 1. **“动静”偷换**：
>    - 装饰器模式是**动态**增加职责（运行时组合），继承是**静态**增加职责（编译时固定）。
>    - 桥接模式将抽象与实现解耦，使二者可以**独立变化**。
> 2. **树形结构的绝对标志**：凡是题干中出现“部分-整体层次结构”、“树形结构”、“客户希望对单个对象和组合对象的使用具有一致性”，100% 对应**组合模式 (Composite)**！
> 3. **算法族的绝对标志**：凡是题干出现“定义一系列算法，把它们封装起来，并且使它们可以相互替换”，100% 对应**策略模式 (Strategy)**！
> 4. **状态与行为绑定的绝对标志**：凡是题干出现“对象内部状态改变时改变其行为，看起来好像修改了其类”，100% 对应**状态模式 (State)**！

## 三、 典型真题溯源与验证

### 【真题精选 1】（考查范围分类：类模式 vs 对象模式）
**题干**：在 GoF 设计模式中，属于类结构型模式的是（ ）。
A. 桥接模式  
B. 装饰器模式  
C. 适配器模式（类版本）  
D. 组合模式  

**【答案】**：**C**  
**【解析】**：
在 GoF 结构型模式中，桥接、装饰、组合、代理、外观、享元均通过对象组合实现，属于对象结构型模式；只有适配器模式存在类适配器（通过继承被适配者类与实现目标接口）和对象适配器两种版本。其中**类适配器**属于唯一的类结构型模式。

---

### 【真题精选 2】（考查意图与应用场景匹配）
**题干**：某软件公司欲开发一个跨平台的图形编辑软件，要求该软件能够在不同的操作系统（如 Windows、Linux、macOS）上绘制不同类型的图形（如圆形、矩形、三角形）。为了使图形形状的扩充和操作系统的适配互不影响，能够独立进行扩展，最适合采用的设计模式是（ ）。
A. 适配器模式  
B. 桥接模式  
C. 装饰器模式  
D. 门面模式  

**【答案】**：**B**  
**【解析】**：
系统存在两个独立变化的维度：操作系统平台（实现维度）和图形形状（抽象维度）。桥接模式（Bridge）的核心意图就是“将抽象部分与它的实现部分分离，使它们都可以独立地变化”，通过面向对象组合替代多层继承，有效避免类爆炸问题。
