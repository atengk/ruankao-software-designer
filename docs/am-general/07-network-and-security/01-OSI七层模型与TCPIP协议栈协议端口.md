### 3. TCP 与 UDP 核心机制全解

| 对比维度 | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
| :--- | :--- | :--- |
| **连接状态** | **面向连接**（需经过三次握手建立连接，四次挥手拆除连接） | **无连接**（直接封装发送数据报，无握手开销） |
| **可靠性保障** | **可靠交付**（通过序号机制、确认应答 ACK、超时重传、校验和保证无差错、不丢失、不重复） | **不可靠交付**（尽最大努力交付，不保证顺序与重传） |
| **传输模式** | **面向字节流**（视为无结构的连续流，动态切分） | **面向报文**（保留应用层完整报文边界） |
| **首部开销** | 首部较长（**最小 20 字节**，最大可扩展至 60 字节） | 首部极小（**固定 8 字节**），额外协议开销极低 |
| **流控与拥塞** | 支持滑动窗口流量控制，以及慢开始、拥塞避免、快重传、快恢复 | 无拥塞控制，不根据网络状况主动限速 |
| **典型应用场景**| 网页浏览 (HTTP/HTTPS)、文件传输 (FTP)、电子邮件 (SMTP) | 实时视频流、音视频电话 (VoIP)、在线游戏、DNS 单次查询 |

## 二、 分析模型与网络通信工作流

### 1. 数据封装与解封装工作流

```
发送方主机                                       接收方主机
[应用层]  数据报文 (Message)                     [应用层]  数据报文 (Message)
   │ 封装应用层首部                                 ▲ 解封装
   ▼                                                │
[传输层]  TCP/UDP首部 + 报文 = 报文段 (Segment)   [传输层]  剥离 TCP/UDP 首部
   │ 封装传输层首部                                 ▲ 解封装
   ▼                                                │
[网络层]  IP首部 + 报文段 = IP数据报 (Packet)      [网络层]  剥离 IP 首部
   │ 封装网络层首部                                 ▲ 解封装
   ▼                                                │
[链路层]  帧头 + IP数据报 + 帧尾 (FCS) = 帧 (Frame)[链路层]  校验 FCS 并剥离帧头帧尾
   │ 封装物理介质编码                               ▲ 接收比特流
   ▼                                                │
[物理层]  01010101... 比特流 ─────────────────────► [物理层]
```

### 2. 网络设备与冲突域/广播域隔离矩阵

| 设备名称 | 工作的最高层次 | 能否隔离冲突域？ | 能否隔离广播域？ |
| :--- | :---: | :---: | :---: |
| **集线器 (Hub) / 中继器** | **第 1 层 (物理层)** | **否**（所有端口属于同一冲突域） | **否** |
| **交换机 (Switch) / 网桥** | **第 2 层 (数据链路层)**| **是**（**每个端口是一个独立的冲突域**） | **否**（默认同一 VLAN 属于同一广播域） |
| **路由器 (Router)** | **第 3 层 (网络层)** | **是** | **是**（**每个接口隔离一个广播域**，阻断广播风暴） |

## 三、 命题题眼与陷阱防御

> [!CAUTION]
> ### 🚨 常见命题陷阱盘点
> 1. **FTP 的双端口角色辨析**：
>    - 控制端口为 **21**（负责用户鉴权与发送控制命令，生命周期贯穿始终）；
>    - 数据端口为 **20**（仅在主动模式 PORT 传输文件数据时开启）。
> 2. **邮件协议的“发”与“收”混淆**：
>    - **发送邮件**只有 **SMTP**（TCP 25 端口）；
>    - **拉取接收邮件**为 **POP3**（TCP 110）或 **IMAP4**（TCP 143）。
> 3. **ARP 协议的解析方向与层次**：
>    - **ARP（地址解析协议）**：将已知的 **IP 地址解析为物理硬件 MAC 地址**；
>    - **RARP（反向地址解析协议）**：将 MAC 地址解析为 IP 地址；
>    - ARP 虽然在数据链路层之上通信，但在软考标准答案中，常归属于**网络层**。
> 4. **交换机 vs 路由器的域隔离能力**：
>    - 交换机隔离**冲突域**，不隔离广播域；路由器**既隔离冲突域，又隔离广播域**！

## 四、 典型真题溯源与逐项排错解析 (Distractor Analysis)

### 【真题精选 1】（考查网络协议与端口号匹配 · 2023上-上午-Q66）
**题干**：在 Internet 网络应用中，协议和默认端口号对应关系正确的是（ ）。
A. DNS 使用 TCP 80 端口  
B. SMTP 使用 TCP 110 端口  
C. HTTPS 使用 TCP 443 端口  
D. SNMP 使用 TCP 161 端口  

- **【正确答案】**：**C**
- **【核心切入点】**：识记传输层协议与知名端口映射矩阵。

#### 逐项排错剖析 (Distractor Analysis)
- **选项 A 错误**：DNS（域名解析协议）默认使用 **UDP 53** 端口（仅区域传送时用 TCP 53）；TCP 80 是非加密 HTTP 协议的端口。
- **选项 B 错误**：SMTP（简单邮件传输协议）默认使用 **TCP 25** 端口；TCP 110 是接收邮件协议 POP3 的默认端口。
- **选项 C 正确**：HTTPS（基于 TLS/SSL 的超文本传输协议）默认使用 **TCP 443** 端口。
- **选项 D 错误**：SNMP（简单网络管理协议）基于 **UDP** 协议运行，使用 UDP 161 端口，而非 TCP。

---

### 【真题精选 2】（考查网络互联设备与冲突域广播域隔离 · 2022下-上午-Q66）
**题干**：某单位内部局域网由若干台以太网交换机互联，每个部门分配一个子网。关于该局域网中的设备行为，下列说法正确的是（ ）。
A. 以太网交换机的每个端口属于同一个冲突域  
B. 路由器能够有效隔离广播域，阻止广播报文跨网段扩散  
C. 集线器可以根据 MAC 地址表进行帧的精准硬件转发  
D. 数据链路层的网桥不能隔离冲突域  

- **【正确答案】**：**B**
- **【核心切入点】**：把握集线器、交换机、路由器三者的核心转发原理与广播域隔离特性。

#### 逐项排错剖析 (Distractor Analysis)
- **选项 A 错误**：以太网交换机的核心优势在于**每个端口都是一个独立的冲突域**，从而彻底消除了以太网 CSMA/CD 碰撞。
- **选项 B 正确**：路由器工作在第三层（网络层），基于 IP 寻址转发，默认情况下不会转发广播报文，能有效实现**广播域隔离**。
- **选项 C 错误**：集线器 (Hub) 工作在物理层，仅负责电信号的简单中继放大，没有 MAC 地址表，只能盲目广播；利用 MAC 地址表转发的是二层交换机。
- **选项 D 错误**：网桥工作在数据链路层，能够基于 MAC 地址进行过滤和转发，能够有效隔离冲突域。
