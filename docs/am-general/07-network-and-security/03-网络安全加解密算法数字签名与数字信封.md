## 一、 核心考纲与概念辨析

### 1. 对称密码 vs 非对称密码体制全景对比

| 对比维度 | 对称加密体制 (Symmetric) | 非对称加密体制 (Asymmetric / 公钥密码) |
| :--- | :--- | :--- |
| **密钥机制** | **加密密钥与解密密钥完全相同**（同源单密钥） | **拥有公钥（Public Key）和私钥（Private Key）密钥对**；公钥向全网公开，私钥由所有者绝对私密保存 |
| **加解密运算速度** | **计算速度极快**，硬件/软件实现效率极高 | **计算速度缓慢**（涉及大整数模乘幂运算），通常比对称加密慢数千倍 |
| **适用业务场景** | **适合加密传输海量数据明文**（如大数据流、音视频媒体、会话通信数据） | **适合加密短小数据（如对称密钥）或用于数字签名与身份认证** |
| **密钥分发与管理** | 密钥管理难度极大，$n$ 个用户双向保密通信需维护 $\frac{n(n-1)}{2}$ 个密钥 | 密钥管理极简单，$n$ 个用户全网仅需维护 $2n$ 个密钥（$n$ 对） |
| **常见标准算法** | **DES** (56位有效密钥), **3DES** (112/168位), **AES** (128/192/256位), **RC4** (流密码), **IDEA**, **SM4** (国密) | **RSA** (基于大素数分解), **ECC** (基于椭圆曲线离散对数), **ElGamal**, **SM2** (国密) |

---

### 2. 消息摘要算法 (Hash)

- **核心定义**：将任意长度的输入消息转换为**固定长度**的输出值（即消息指纹/数字摘要）。
- **三大单向散列特性**：
  1. **单向性 (One-way)**：由明文极易计算出摘要，但由摘要在计算上无法逆推反解出明文；
  2. **雪崩效应 (Avalanche Effect)**：明文即使仅变动 1 个比特，产生的摘要散列值也会产生颠覆性巨大变化；
  3. **抗碰撞性 (Collision Resistance)**：在计算上不可能找到两篇产生相同摘要的不同明文。
- **高频摘要算法及输出长度（必考）**：
  - **MD5**：输出 **128 位**（16 字节）散列值；
  - **SHA-1**：输出 **160 位**（20 字节）散列值；
  - **SHA-256**：输出 **256 位**（32 字节）散列值；
  - **SM3** (国密)：输出 **256 位** 散列值。

### 3. 国家网络安全等级保护 2.0 (等保 2.0) 框架

《信息安全技术 网络安全等级保护基本要求》(GB/T 22239-2019) 规定了五个安全保护等级：

| 等级名称 | 等级保护级别 | 侵害客体与后果严重程度 | 典型适用系统对象 |
| :--- | :---: | :--- | :--- |
| **第一级** | **自主保护级** | 对公民、法人和其他组织的合法权益造成损害，**不损害国家安全、社会秩序和公共利益** | 一般小型企业门户、普通内部测试系统 |
| **第二级** | **指导保护级** | 对公民、法人合法权益造成**严重损害**，或对社会秩序、公共利益造成损害，**不损害国家安全** | 市级单位一般业务系统、中小型互联网平台 |
| **第三级** | **监督保护级** | 对社会秩序和公共利益造成**严重损害**，或**对国家安全造成损害** | **地级市重要机关、金融能源核心系统、三级甲等医院 HIS、云平台** |
| **第四级** | **强制保护级** | 对社会秩序和公共利益造成**特别严重损害**，或**对国家安全造成严重损害** | 国家关键基础设施、国家级政务平台、大型电网调度 |
| **第五级** | **专控保护级** | **对国家安全造成特别严重损害** | 国家极密战略军工、涉及国防命脉的核心系统 |

- **一个中心、三重防护架构**：
  - **一个中心**：安全管理中心；
  - **三重防护**：安全计算环境、安全区域边界、安全通信网络。

---

### 4. 《个人信息保护法》高频法条常识

- **个人信息与敏感个人信息**：
  - **敏感个人信息**：一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到重大危害的个人信息，包括**生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等信息，以及不满十四周岁未成年人的个人信息**；
  - 处理敏感个人信息应当取得个人的**单独同意**。
- **处理原则**：合法、正当、必要和诚信原则；采取对个人权益影响最小的方式（最小必要原则）。

## 二、 分析模型与安全工作流

### 1. 数字签名与身份认证工作流

> [!IMPORTANT]
> 💡 **十六字绝密口诀**：
> - **公钥加密，私钥解密** $\rightarrow$ 用于 **保密通信（防止被偷窥）**！
> - **私钥签名，公钥验签** $\rightarrow$ 用于 **数字签名（身份认证、防篡改、防抵赖）**！

```
【发送方 A】                              【接收方 B】
  明文消息 M ────────(传输明文)────────> 收到明文 M
     │                                    │
   Hash                                 Hash
     ▼                                    ▼
  消息摘要 1                            消息摘要 2 (重新计算)
     │                                    ▲
  【A的私钥加密】                          │ 【A的公钥解密】
     ▼                                    │
  数字签名 S ────────(传输签名)────────> 解密恢复签名 S
                                          ▲
                                   对比 [摘要1 == 摘要2]
                                   一致: 验签成功(未被篡改且确由A发出)
```

- **数字签名的三大安全目标**：
  1. **完整性 (Integrity)**：比对摘要确保传输数据未被篡改；
  2. **身份认证 (Authentication)**：只有 A 拥有 A 的私钥，证明消息确系 A 所发出；
  3. **不可抵赖性 (Non-repudiation)**：发送方无法否认自己曾发出该信息。

---

### 2. 数字信封 (Digital Envelope) 混合密码工作流

数字信封将**对称加密的高性能**与**公钥密码的安全密钥分发**深度融合：

```
发送方 A:
1. 随机生成一次性对称密钥 K (会话密钥)
2. 密文 C = 对称加密(明文 M, 密钥 K)
3. 数字信封 E_K = 非对称加密(密钥 K, 接收方 B 的公钥)
4. 将 [密文 C + 数字信封 E_K] 打包发送给 B ───►

接收方 B:
1. 密钥 K = 非对称解密(数字信封 E_K, 接收方 B 的私钥)  (拆开信封)
2. 明文 M = 对称解密(密文 C, 密钥 K)                   (恢复明文)
```

## 三、 命题题眼与陷阱防御

> [!CAUTION]
> ### 🚨 常见命题陷阱盘点
> 1. **数字签名私钥归属混淆**：
>    - 题目：A 向 B 发送签名信息，A 应该使用谁的密钥签名？B 应该使用谁的密钥验签？
>    - 规则：**A 使用 A 自己的私钥签名；B 使用 A 的公钥验签**！出题人常设置“使用 B 的私钥”作为干扰项。
> 2. **数字信封公钥归属混淆**：
>    - 题目：制作数字信封封装会话密钥时，应使用谁的公钥？
>    - 规则：**必须使用接收方 B 的公钥加密**！因为只有接收方 B 掌握自己的私钥，才能解密取出对称密钥。
> 3. **等保 2.0 三级系统保护要求**：
>    - 软考常考“涉及地市级机关政务、三级甲等医院核心系统应达到的等级保护级别是（ ）”，唯一答案为**第三级（监督保护级）**！
> 4. **敏感个人信息中未成年人年龄红线**：
>    - 法律规定不满 **十四周岁** 未成年人的个人信息属于敏感个人信息，防范十八周岁干扰项。

## 四、 典型真题溯源与逐项排错解析 (Distractor Analysis)

### 【真题精选 1】（考查数字签名机制中的密钥使用 · 2023上-上午-Q7~8）
**题干**：Alice 向 Bob 发送一段经过数字签名的信息，Alice 应该使用（ ）对信息摘要进行加密生成数字签名；Bob 收到信息后，应该使用（ ）对签名进行解密验证。
(1) A. Alice 的私钥  B. Alice 的公钥  C. Bob 的私钥  D. Bob 的公钥  
(2) A. Alice 的私钥  B. Alice 的公钥  C. Bob 的私钥  D. Bob 的公钥  

- **【正确答案】**：**(1) A  (2) B**
- **【核心切入点】**：把握“私钥签名、公钥验签”的不可伪造性原理。

#### 逐项排错剖析 (Distractor Analysis)
- **第 (1) 空排错**：
  - 数字签名的目的是证明身份并抗抵赖，只有 Alice 本人拥有 Alice 的私钥，因此 Alice 必须使用 **Alice 的私钥** 加密消息摘要生成数字签名。
  - **选项 A 正确**；选项 B（公钥是公开的，任何人都能用公钥加密，起不到签名防伪作用）；选项 C/D（Alice 根本不拥有 Bob 的私钥，且签名与 Bob 的密钥无关）。
- **第 (2) 空排错**：
  - Bob 收到后，为了验证签名是否确实由 Alice 发出，必须使用 **Alice 的公钥** 对签名进行解密还原出消息摘要。
  - **选项 B 正确**；选项 A（Bob 绝不可能拥有 Alice 的私钥）；选项 C/D（Bob 的密钥不能用于验证 Alice 的签名）。

### 【真题精选 2】（考查数字信封工作机制 · 2022下-上午-Q8）
**题干**：在数字信封技术中，发送方使用（ ）加密待发送的对称密钥，接收方使用（ ）解密该数字信封获取对称密钥。
A. 发送方的私钥；接收方的公钥  
B. 发送方的公钥；接收方的私钥  
C. 接收方的公钥；接收方的私钥  
D. 接收方的私钥；接收方的公钥  

- **【正确答案】**：**C**
- **【核心切入点】**：数字信封用于保密传输对称会话密钥，数据流向是发给接收方，只有接收方需要拆封，故采用接收方公钥加密、接收方私钥解密。

#### 逐项排错剖析 (Distractor Analysis)
- **选项 A 错误**：发送方用自己的私钥加密，任何拥有发送方公钥的人都能解开，根本起不到保密保护对称密钥的作用。
- **选项 B 错误**：发送方用自己的公钥加密，只有发送方自己的私钥能解开，接收方拿到后根本无法解密。
- **选项 C 正确**：发送方使用接收方的公钥加密对称密钥生成信封；接收方收到后，使用只有自己持有的私钥拆解信封，完美保证机密性。
- **选项 D 错误**：颠倒了公钥和私钥的常规使用规则。

### 【真题精选 3】（考查网络安全等级保护 2.0 定级 · 2021下-上午-Q13）
**题干**：依据《信息安全技术 网络安全等级保护基本要求》，网络安全保护等级分为五级。某市级公立三级甲等医院的医院信息系统 (HIS) 一旦遭到破坏，会对社会秩序和公共利益造成严重损害，该系统应定级为（ ）。
A. 第一级（自主保护级）  
B. 第二级（指导保护级）  
C. 第三级（监督保护级）  
D. 第四级（强制保护级）  

- **【正确答案】**：**C**
- **【核心切入点】**：识记等保 2.0 定级矩阵，对社会秩序和公共利益造成“严重损害”对应第三级。

#### 逐项排错剖析 (Distractor Analysis)
- **选项 A (第一级) 错误**：第一级仅对公民组织自身造成损害，不损害公共利益。
- **选项 B (第二级) 错误**：第二级仅对社会秩序和公共利益造成“一般损害”，尚未达到严重损害标准。
- **选项 C (第三级) 正确**：对社会秩序和公共利益造成严重损害，或对国家安全造成损害，严格归为**第三级（监督保护级）**。三甲医院核心业务系统属于典型的等保三级保护对象。
- **选项 D (第四级) 错误**：第四级对应对国家安全造成严重损害或对公共利益造成“特别严重损害”，通常为国家战略关键基础设施。
