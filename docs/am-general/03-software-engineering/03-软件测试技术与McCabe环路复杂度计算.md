## 一、 核心考纲与概念辨析

### 1. 黑盒测试 vs 白盒测试方法全景

| 测试类别 | 测试方法 | 核心设计逻辑与测试用例设计依据 | 典型命题考点 |
| :--- | :--- | :--- | :--- |
| **黑盒测试**<br>(功能测试/数据驱动)<br>*不考虑程序内部结构，仅依据需求规格检验输入与输出* | **等价类划分** | 将输入域划分为有效等价类和无效等价类，从各类中选取少数代表性数据 | 设计用例需覆盖所有有效等价类与每个无效等价类 |
| | **边界值分析** | 选取正好等于、刚好大于、刚好小于边界的值（$n-1, n, n+1$） | **最有效的黑盒方法**，大量错误发生在输入范围的边界上 |
| | **错误推测法** | 凭测试人员的工程经验与直觉推测易出错的特殊输入（如 0、空串、极大负数） | 辅助补充用例 |
| | **因果图法** | 分析多种输入条件的组合以及输入与输出之间的因果约束逻辑 | 适合输入条件存在复杂逻辑依赖的场景 |
| **白盒测试**<br>(结构测试/逻辑驱动)<br>*依据程序内部控制流逻辑设计测试用例* | **逻辑覆盖测试** | 逐层深入检验程序内部的语句、判定分支与逻辑条件 | 6 种覆盖强度递增等级 |
| | **基本路径测试** | 依据控制流图计算环路复杂度，导出线性无关的独立路径集合 | **必考 McCabe 环路复杂度计算** |

### 2. 白盒逻辑覆盖准则强度梯队（由弱到强）

$$\text{语句覆盖} < \text{判定覆盖} < \text{条件覆盖} < \text{判定/条件覆盖} < \text{条件组合覆盖} < \text{路径覆盖}$$

| 覆盖级别 | 核心要求与判定标准 | 局限性与盲区 |
| :--- | :--- | :--- |
| **语句覆盖** | 每个可执行语句至少执行一次 | **最弱的覆盖准则**，无法发现判定分支逻辑错误 |
| **判定覆盖 (分支覆盖)** | 每个判定的“真”和“假”分支至少经历一次 | 判定内的子条件可能未全部经历真假 |
| **条件覆盖** | 每个判定中的每个逻辑条件的真值和假值至少满足一次 | 不能保证每个判定的分支（整体结果）都被遍历 |
| **判定/条件覆盖** | 同时满足判定覆盖和条件覆盖的要求（整体真假与内部子条件真假均覆盖） | 未考虑子条件间的各种逻辑组合关系 |
| **条件组合覆盖** | 每个判定中各个子条件的各种可能取值组合至少出现一次 | 使每个判定中所有条件取值的全组合均被覆盖，但仍不能保证覆盖全部路径 |
| **路径覆盖** | 程序中每一条可能的独立执行路径都至少经历一次 | **最强的逻辑覆盖**，但在存在多重循环时可能导致路径爆炸 |

### 3. McCabe 环路复杂度计算模型（必考大分项）

环路复杂度（Cyclomatic Complexity, 记作 $V(G)$）用于衡量程序的控制逻辑复杂度，代表程序**独立线性无关基本路径的上限**。

#### 三大通用等价计算公式

1. **公式一（边与节点数公式）**：
   $$V(G) = m - n + 2$$
   - $m$：控制流图中的**有向弧（边）的条数**；
   - $n$：控制流图中的**节点数（操作或判定框）**。

2. **公式二（闭合平面区域数公式）**：
   $$V(G) = R = \text{平面闭合区域数} + 1$$
   - 控制流图将平面切分成若干个由边围成的闭合区域，再加上图外部的 1 个无界大区域。

3. **公式三（判定节点数公式，最快速秒杀题）**：
   $$V(G) = P + 1$$
   - $P$：控制流图中**包含判断逻辑的节点数（出度 $\ge 2$ 的节点数）**。
   - **极速秒杀准则**：在程序源码中，只需数出 `if`、`while`、`for`、`case` 等分支判断关键字的个数，直接 $+ 1$ 即为环路复杂度！

### 4. 软件维护四大类型对比（高频记忆考点）

| 维护类型 | 触发原因与维护目标 | 典型案例 | 工作量占比 |
| :--- | :--- | :--- | :--- |
| **完善性维护 (Perfective)** | 为满足用户提出的**新需求、增加新功能或提升性能与可维护性**而修改软件 | 增加导出 Excel 功能、优化查询响应速度 | **占比最高！约 50% ~ 60%** |
| **适应性维护 (Adaptive)** | 为适应**外部运行环境（操作系统版本、数据库、外部网络接口、硬件）变化**而修改软件 | 系统从 Win 10 迁移至 Win 11、适配最新 JDK | 约 25% |
| **改正性维护 (Corrective)** | 修复交付使用后在运行过程中暴露出的**隐藏缺陷、程序 Bug 或逻辑错误** | 修复空指针异常、修补浮点数计算四舍五入偏差 | 约 15% ~ 20% |
| **预防性维护 (Preventive)** | 为防范未来潜在的风险或便于日后维护，**主动进行架构重构或引入新技术** | 模块解耦重构、增加工程自动化单元测试 | 约 5% |

## 二、 命题题眼与陷阱防御

> [!CAUTION]
> ### 🚨 常见命题陷阱盘点
> 1. **McCabe 节点与边的计算陷阱**：
>    - 复合条件判定：若判定条件为 `if (A && B)`，在画控制流图时必须拆分为两个单一判定节点！若不拆分直接套用 $m-n+2$ 极易算错；此时使用 $P+1$ 只要把 `&&` 和 `||` 视作额外的判定点即可。
> 2. **软件维护占比判断**：
>    - 软考常考“在软件维护的各项活动中，工作量占比最大的是哪一种？” 80% 的新手会误选“改正性维护”（误以为改 Bug 最耗时），标准答案 100% 为**完善性维护**（满足业务变化与扩展新需求）！
> 3. **边界值测试的选点原则**：
>    - 若有效输入范围为 $[1, 100]$，边界值应选取：$0, 1, 100, 101$；千万不要只测有效边界 $1$ 和 $100$ 而漏掉无效边界 $0$ 和 $101$。

## 三、 典型真题溯源与验证

### 【真题精选 1】（考查 McCabe 环路复杂度计算）
**题干**：某程序流程图中共有 14 条有向边，9 个节点，则该控制流图的 McCabe 环路复杂度 $V(G)$ 为（ ）。
A. 5  
B. 6  
C. 7  
D. 8  

**【答案】**：**C**  
**【解析】**：
直接套用边节点公式：
$$V(G) = m - n + 2 = 14 - 9 + 2 = 7$$
因此该程序包含的线性无关独立路径数为 7，答案选 C。

### 【真题精选 2】（考查软件维护类型识别）
**题干**：某公司自主开发的财务管理系统由于税收政策的调整，需要修改部分个人所得税税率计算模块；同时为了支持即将来临的双十一活动，针对核心结算接口进行了并发性能优化以缩短响应时间。这两项维护活动分别属于（ ）。
A. 适应性维护；完善性维护  
B. 改正性维护；适应性维护  
C. 完善性维护；预防性维护  
D. 适应性维护；改正性维护  

**【答案】**：**A**  
**【解析】**：
- 税收政策调整属于外部业务规则与法律运行环境的变更，系统为此进行适配属于**适应性维护 (Adaptive)**；
- 对核心结算接口进行并发性能优化、缩短响应时间属于提升软件现有性能质量指标，属于**完善性维护 (Perfective)**。故选 A。
