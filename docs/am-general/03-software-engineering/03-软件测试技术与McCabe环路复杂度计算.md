## 一、 核心考纲与概念辨析

### 1. 黑盒测试 vs 白盒测试方法全景

| 测试类别 | 测试方法 | 核心设计逻辑与测试用例设计依据 | 典型命题考点 |
| :--- | :--- | :--- | :--- |
| **黑盒测试**<br>(功能测试/数据驱动)<br>*不考虑程序内部结构，仅依据需求规格检验输入与输出* | **等价类划分** | 将输入域划分为有效等价类和无效等价类，从各类中选取少数代表性数据 | 设计用例需覆盖所有有效等价类与每个无效等价类 |
| | **边界值分析** | 选取正好等于、刚好大于、刚好小于边界的值（$n-1, n, n+1$） | **最有效的黑盒方法**，大量错误发生在输入范围的边界上 |
| | **错误推测法** | 凭测试人员的工程经验与直觉推测易出错的特殊输入（如 0、空串、极大负数） | 辅助补充用例 |
| | **因果图法** | 分析多种输入条件的组合以及输入与输出之间的因果约束逻辑 | 适合输入条件存在复杂逻辑依赖的场景 |
| **白盒测试**<br>(结构测试/逻辑驱动)<br>*依据程序内部控制流逻辑设计测试用例* | **逻辑覆盖测试** | 逐层深入检验程序内部的语句、判定分支与逻辑条件 | 6 种覆盖强度递增等级 |
| | **基本路径测试** | 依据控制流图计算环路复杂度，导出线性无关的独立路径集合 | **必考 McCabe 环路复杂度计算** |

### 2. 白盒逻辑覆盖准则强度梯队（由弱到强排列）

$$\text{语句覆盖} < \text{判定覆盖} < \text{条件覆盖} < \text{判定/条件覆盖} < \text{条件组合覆盖} < \text{路径覆盖}$$

| 覆盖级别 | 核心要求与判定标准 | 局限性与盲区 |
| :--- | :--- | :--- |
| **语句覆盖** | 每个可执行语句至少执行一次 | **最弱的覆盖准则**，无法发现判定分支逻辑错误 |
| **判定覆盖 (分支覆盖)** | 每个判定的“真”和“假”分支至少经历一次 | 判定内的子条件可能未全部经历真假 |
| **条件覆盖** | 每个判定中的每个逻辑条件的真值和假值至少满足一次 | 不能保证每个判定的分支（整体结果）都被遍历 |
| **判定/条件覆盖** | 同时满足判定覆盖和条件覆盖的要求（整体真假与内部子条件真假均覆盖） | 未考虑子条件间的各种逻辑组合关系 |
| **条件组合覆盖** | 每个判定中各个子条件的各种可能取值组合至少出现一次 | 使每个判定中所有条件取值的全组合均被覆盖，但仍不能保证覆盖全部路径 |
| **路径覆盖** | 程序中每一条可能的独立执行路径都至少经历一次 | **最强的逻辑覆盖**，但在存在多重循环时可能导致路径爆炸 |

### 3. 软件维护四大类型对比（高频记忆考点）

| 维护类型 | 触发原因与维护目标 | 典型案例 | 工作量占比 |
| :--- | :--- | :--- | :--- |
| **完善性维护 (Perfective)** | 为满足用户提出的**新需求、增加新功能或提升性能与可维护性**而修改软件 | 增加导出 Excel 功能、优化查询响应速度 | **占比最高！约 50% ~ 60%** |
| **适应性维护 (Adaptive)** | 为适应**外部运行环境（操作系统版本、数据库、外部网络接口、硬件）变化**而修改软件 | 系统从 Win 10 迁移至 Win 11、适配最新 JDK | 约 25% |
| **改正性维护 (Corrective)** | 修复交付使用后在运行过程中暴露出的**隐藏缺陷、程序 Bug 或逻辑错误** | 修复空指针异常、修补浮点数计算四舍五入偏差 | 约 15% ~ 20% |
| **预防性维护 (Preventive)** | 为防范未来潜在的风险或便于日后维护，**主动进行架构重构或引入新技术** | 模块解耦重构、增加工程自动化单元测试 | 约 5% |

## 二、 计算公式与分析模型

### 1. McCabe 环路复杂度三大计算公式

环路复杂度（Cyclomatic Complexity，记作 $V(G)$）代表程序控制流图中**线性无关的独立基本路径数上限**。

1. **公式一（边与节点数公式）**：
   $$V(G) = m - n + 2$$
   - $m$：控制流图中的**有向弧（边）的条数**；
   - $n$：控制流图中的**节点数（操作或判定框）**。
2. **公式二（闭合平面区域数公式）**：
   $$V(G) = R = \text{平面闭合区域数} + 1$$
   - 控制流图将二维平面切分成若干个由有向边围成的闭合区域，再加上图外部的 1 个无界大区域。
3. **公式三（判定节点数公式 · 快速秒杀）**：
   $$V(G) = P + 1$$
   - $P$：控制流图中**包含判断逻辑的节点数（出度 $\ge 2$ 的节点数）**。
   - **源码极速秒杀口诀**：直接数出源码中 `if`、`while`、`for`、`case` 等分支判断关键字的个数，直接 $+ 1$ 即为环路复杂度！

### 2. 复合条件判定的节点拆分模型

若源码中存在复合逻辑判定（如 `if (A && B)` 或 `if (C || D)`），**不能将其视为单个判定节点**：
- `A && B`：必须在控制流图中拆解为两个串行判定节点，或者按布尔运算符个数算作 2 个判定条件（即 $P = 2$）；
- 否则直接套用 $m - n + 2$ 时若未拆分节点将产生严重计算偏差。

## 三、 命题题眼与陷阱防御

> [!CAUTION]
> ### 🚨 常见命题陷阱盘点
> 1. **软件维护占比的直觉陷阱**：
>    - 软考常考“在各类软件维护活动中，工作量占比最大的是哪一种？” 80% 的考生凭直觉误选“改正性维护”（误以为修 Bug 最费时间），标准答案 100% 为**完善性维护**（扩展新功能与优化性能占比超过 50%）！
> 2. **最弱与最强逻辑覆盖**：
>    - 最弱逻辑覆盖：**语句覆盖**（仅执行每条语句一次，漏测大量分支）；
>    - 最强逻辑覆盖：**路径覆盖**（遍历所有可能执行路径）。
> 3. **边界值测试的选点原则**：
>    - 若有效输入范围为 $[1, 100]$，边界值应选取：$0, 1, 100, 101$；切忌只测内部有效边界 $1$ 和 $100$ 而漏掉外部无效边界 $0$ 和 $101$。

## 四、 典型真题溯源与逐项排错解析 (Distractor Analysis)

### 【真题精选 1】（考查 McCabe 环路复杂度公式推导 · 2023上-上午-Q21）
**题干**：某程序流程图中共有 14 条有向边，9 个节点，则该控制流图的 McCabe 环路复杂度 $V(G)$ 为（ ）。
A. 5  
B. 6  
C. 7  
D. 8  

- **【正确答案】**：**C**
- **【核心考点】**：McCabe 环路复杂度边节点公式 $V(G) = m - n + 2$。
- **【逐项排错剖析】**：
  - **A 选项排除**：5 是误按 $m - n = 14 - 9 = 5$ 计算，遗漏了常数项 $+ 2$；
  - **B 选项排除**：6 是误按 $m - n + 1 = 6$ 计算，混淆了平面连通图判定公式；
  - **C 选项正确**：代入标准公式 $V(G) = 14 - 9 + 2 = 7$，意味着该模块至少需要设计 7 条测试用例方能实现基本路径覆盖；
  - **D 选项排除**：8 计算结果有误。

### 【真题精选 2】（考查软件维护类型识别 · 2022下-上午-Q22）
**题干**：某公司自主开发的财务管理系统由于国家税收政策的调整，需要修改部分个人所得税税率计算模块；同时为了支持即将来临的双十一活动，针对核心结算接口进行了并发性能优化以缩短响应时间。这两项维护活动分别属于（ ）。
A. 适应性维护；完善性维护  
B. 改正性维护；适应性维护  
C. 完善性维护；预防性维护  
D. 适应性维护；改正性维护  

- **【正确答案】**：**A**
- **【核心考点】**：软件维护四大类型的业务触发机理与适用场景。
- **【逐项排错剖析】**：
  - **A 选项正确**：国家税收政策调整属于外部业务规则与法律运行环境的变更，系统为此进行适配属于**适应性维护 (Adaptive)**；对接口进行高并发性能调优以缩短响应时间，属于提升现有软件运行品质，属于**完善性维护 (Perfective)**；
  - **B 选项排除**：改正性维护是针对软件运行中暴露出的隐藏错误或 Bug（如报错挂掉），税率调整属于环境与政策合规变化，非原系统代码有 Bug；
  - **C 选项排除**：预防性维护是面向未来主动进行的架构重构或单元测试补齐，针对双十一具体性能指标进行的压测优化属于完善性维护；
  - **D 选项排除**：性能优化不属于改正性维护。

### 【真题精选 3】（考查白盒逻辑覆盖强度等级 · 2023下-上午-Q23）
**题干**：在白盒测试方法中，测试用例设计要求“程序中每个判定的真分支和假分支都至少经历一次”。这种覆盖准则称为（ ），在以下四种逻辑覆盖中，覆盖强度最高的是（ ）。
(1) A. 语句覆盖  B. 判定覆盖  C. 条件覆盖  D. 路径覆盖  
(2) A. 语句覆盖  B. 判定覆盖  C. 条件组合覆盖  D. 判定/条件覆盖  

- **【正确答案】**：**(1) B  (2) C**
- **【核心考点】**：白盒逻辑覆盖准则的定义与覆盖强度梯队关系。
- **【逐项排错剖析】**：
  - **第 (1) 题排错**：
    - **A 选项排除**：语句覆盖要求每个可执行语句执行一次，不能保证每个分支均被遍历；
    - **B 选项正确**：判定覆盖（又称分支覆盖）的核心定义就是使每个判定的真、假分支都至少被执行一次；
    - **C 选项排除**：条件覆盖关注的是每个判定内部每个原子条件的真假，不能保证整体分支被覆盖；
    - **D 选项排除**：路径覆盖关注的是整条执行路径全集。
  - **第 (2) 题排错**：
    - **C 选项正确**：强度梯队为“语句 < 判定 < 条件 < 判定/条件 < 条件组合 < 路径”。在给出的四个选项中，**条件组合覆盖**满足了所有判定内部条件的全部真假取值组合，覆盖强度最高；
    - **A、B、D 选项排除**：强度均低于条件组合覆盖。
