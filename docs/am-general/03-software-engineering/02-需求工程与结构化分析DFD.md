## 一、 核心考纲与概念辨析

### 1. 需求工程全景生命周期

需求工程分为**需求开发**与**需求管理**两大领域：

```
需求工程
├── 需求开发
│   ├── 需求获取 (Elicitation)：访谈、问卷调查、原型法、现场观摩、联合应用开发 (JAD)
│   ├── 需求分析 (Analysis)：建立领域分析模型（结构化 SA 或面向对象 OOA），消除二义性与冲突
│   ├── 需求规格说明 (Specification)：输出统一标准的《软件需求规格说明书》(SRS)
│   └── 需求验证 (Validation)：需求评审、原型走查，确保正确性、无二义性、可验证性
└── 需求管理
    ├── 需求基线 (Baseline) 变更控制与变更审批委员会 (CCB)
    └── 需求跟踪矩阵 (RTM)：前向跟踪（需求 $\rightarrow$ 设计/编码）与后向跟踪（代码 $\rightarrow$ 需求）
```

---

### 2. 数据流图 (DFD) 四大核心图元（贯通下午题 1）

数据流图是结构化分析（SA）的核心建模工具，描述系统中数据的流动、转换与存储：

| DFD 图元名称 | 图形符号 (Yourdon / DeMarco 风格) | 语义含义与规则约束 | 软考常见命题漏洞 |
| :--- | :--- | :--- | :--- |
| **外部实体 (Entity)** | **矩形框** | 系统外部的人员、组织、外部设备或第三方软件系统（数据的源点或终点） | 实体存在于系统边界之外，不属于系统内部构件 |
| **加工 / 处理 (Process)** | **圆形或圆角矩形** | 对数据进行转换、计算或处理的操作逻辑，必须包含输入和输出 | 加工必须能够依据输入生成输出，有编号（如 1.1, 1.2） |
| **数据存储 (Data Store)** | **双平行横线（或右开口矩形）** | 系统内部暂时或长期保存的数据集合（如数据库表、文件、缓存） | 数据存储必须通过加工进行读写，不能自发流向实体 |
| **数据流 (Data Flow)** | **带箭头的直线或弧线** | 处于流动状态的数据，箭头标明流动方向，必须标有数据名称 | 两个加工之间的数据流表示中间处理结果 |

---

### 3. 数据字典 (DD) 符号体系速查

数据字典是对数据流图所有元素（数据流、数据项、数据存储、加工）的精确文字定义：

| 符号 | 含义 | 示例 | 释义 |
| :--- | :--- | :--- | :--- |
| `=` | 被定义为 | `客户信息 = 姓名 + 手机号` | 客户信息由姓名和手机号拼接组成 |
| `+` | 顺序连接 / 与 | `A + B` | A 和 B 依次顺序出现 |
| `[ | ]` | 或 / 选择其一 | `支付方式 = [微信支付 | 支付宝 | 银行卡]` | 括号内选项三选一 |
| `{ }` | 重复 | `{订单项}` 或 $1\{\text{订单项}\}10$ | 订单项循环重复出现 1 到 10 次 |
| `( )` | 可选 / 0或1次 | `地址 + (邮编)` | 邮编属于可选字段 |
| `" "` | 基本数据常量 | `"M" | "F"` | 字符串常量枚举 |
| `* *` | 注释 | `*有效身份证件*` | 业务说明与备注 |

## 二、 分析模型与数据流守恒校验模型

### 1. 数据流图四大连线合法性禁区

```
【实体】 ───────> 【实体】      ❌ 非法（系统无法监控外部直接通信，非系统分析职责）
【实体】 ───────> 【数据存储】  ❌ 非法（外部实体不能越过系统加工直接落盘）
【数据存储】 ───> 【外部实体】  ❌ 非法（外部实体不能直接从存储中捞取数据）
【数据存储】 ───> 【数据存储】  ❌ 非法（存储之间不能无加工逻辑自发同步）

【合法原则】数据流必须有至少一端连接到“加工”！
```

### 2. 加工三大经典缺陷分析模型

```
       [黑洞 Black Hole]                 [奇迹 Miracle / 白洞]               [灰洞 Gray Hole]
       ┌───────────────┐                  ┌───────────────┐                  ┌───────────────┐
──In1─>│    加工 P1    │           ──────>│    加工 P2    │──Out1─>    ──In1─>│    加工 P3    │──Out1(含新字段)─>
──In2─>│ (只有入没有出) │                  │ (只有出没有入) │──Out2─>           │ (入不足以产出)│
       └───────────────┘                  └───────────────┘                  └───────────────┘
```

- **黑洞 (Black Hole)**：加工仅有输入流，没有任何输出流，信息凭空消失；
- **奇迹 / 白洞 (Miracle)**：加工没有任何输入流，凭空生成输出流，无中生有；
- **灰洞 (Gray Hole)**：加工有入有出，但输入的属性数据在业务逻辑上根本无法推导生成输出的数据项（如输入仅有“学生学号”，输出却生成了“学生家庭住址及银行卡余额”）。

## 三、 命题题眼与陷阱防御

> [!CAUTION]
> ### 🚨 常见命题陷阱盘点
> 1. **顶层图的数据存储陷阱**：
>    - 顶层 DFD 只能有 1 个代表全系统的核心加工与若干外部实体；
>    - **顶层图中原则上不允许出现数据存储**！若选择题中出现“顶层 DFD 包含数据存储”，多为干扰项。
> 2. **父子图平衡守恒规则**：
>    - 子图所有向外发出的数据流与从外部接收的数据流，必须在数量与名称上与父图中该加工所持有的输入/输出流 100% 对应一致。
> 3. **数据字典符号混淆**：
>    - 中括号 `[ | ]` 为选择关系；花括号 `{ }` 为重复；小括号 `( )` 为可选。出题常将“可选”与“选择”偷换符号。

## 四、 典型真题溯源与逐项排错解析 (Distractor Analysis)

### 【真题精选 1】（考查 DFD 数据流合法性判断 · 2023上-上午-Q19）
**题干**：在分层数据流图（DFD）中，下列数据流的起点和终点关系中，（ ）是完全合法的。
A. 从一个外部实体直接流向另一个外部实体  
B. 从一个外部实体直接流向一个数据存储  
C. 从一个数据存储直接流向另一个数据存储  
D. 从一个数据存储流向一个加工，再由该加工流向另一个数据存储  

- **【正确答案】**：**D**
- **【核心考点】**：数据流图语法规则与数据守恒流向约束。
- **【逐项排错剖析】**：
  - **A 选项排除**：两个外部实体之间的数据流属于现实世界的交互，不属于目标软件系统的处理边界，在 DFD 中属非法连接；
  - **B 选项排除**：外部实体不能越过系统加工直接向系统内数据存储写数据，必须经过加工的数据校验与转换；
  - **C 选项排除**：数据存储是静态被动集合，两个存储之间无法自行同步，必须经由加工读出、转换后再写入目标存储；
  - **D 选项正确**：数据从源存储流向加工进行计算处理，处理后的结果数据流再由加工写入目标数据存储，符合合法语法。

---

### 【真题精选 2】（考查数据字典符号语义 · 2022下-上午-Q19）
**题干**：在结构化分析方法中，某数据流由“工号、姓名、性别”三个数据项组成，且“性别”只能是“男”或“女”其中之一；“职务”可能存在也可能不存在。在数据字典中，描述该数据流组成的最恰当表达式是（ ）。
A. 员工信息 = 工号 + 姓名 + [男 | 女] + (职务)  
B. 员工信息 = 工号 + 姓名 + {男 | 女} + [职务]  
C. 员工信息 = 工号 + 姓名 + (男 | 女) + {职务}  
D. 员工信息 = 工号 + 姓名 + [男 , 女] + (职务)  

- **【正确答案】**：**A**
- **【核心考点】**：数据字典核心符号的使用（`+` 顺序连接，`[ | ]` 多选一，`( )` 可选）。
- **【逐项排错剖析】**：
  - **A 选项正确**：`+` 表示顺序连接；`[男 | 女]` 使用方括号加坚线表示二者选其一；`(职务)` 使用圆括号表示字段可选（出现 0 次或 1 次），完全符合题干；
  - **B 选项排除**：`{男 | 女}` 花括号代表循环重复多次，与性别唯一不符；`[职务]` 方括号未提供备选项，语法错误；
  - **C 选项排除**：`(男 | 女)` 圆括号代表可选，意味着性别可以为空，不符合男女必选其一的业务约束；`{职务}` 代表职务重复多次；
  - **D 选项排除**：方括号内的分隔符应为坚线 `|`，而非逗号 `,`。
