# 0007 下午应用技术知识库架构与 Java 实战工程规范

## 背景与上下文

软考软件设计师下午科目（应用技术，75分）为综合案例分析与程序设计，实行“双科同时 $\ge 45$ 分方为及格”的硬性红线。下午题题型高度固定且主观性强，历年考生极易在 DFD 数据流缺失、E-R 关系模式不全或设计模式填空失准上失分。上一会话已全面收官上午综合知识 21 篇精要与全套公式/避坑手册。为了开启下午题攻坚，必须在知识库源目录拓扑、VitePress 路由编排、Java 21 实战验证工程设计以及推进批次上达成明确的架构共识。

## 架构决策

1. **知识库目录与 VitePress 导航拓扑**：
   - 在 `docs/` 下设立标准目录 `docs/pm-application/`，彻底取代原草案占位符 `pm-applied`，与上午题 `docs/am-general/` 保持精准语义对称；
   - 顶部导航栏（Nav）新增【下午应用技术】，侧边栏（Sidebar）系统划分【通关全景与采分模板】及【试题一 至 试题五】各专题专栏；
   - 知识库采用【案例采分四步法】标准体例：① 题型本质与采分标准；② 解题方法论与万能公式；③ 典型机考真题逐层拆解；④ `<details>` 检索式自测与标准答案。

2. **Java 21 实战验证工程（exam-java）**：
   - 在工程根目录建立独立 Maven 子工程 `exam-java/`，与外层 Node.js / VitePress 前端配置物理解耦；
   - 基准环境锁定 Java 21 与 JUnit 5，保持依赖纯粹轻量，杜绝框架黑盒；
   - 采用【双轨实战验证】包结构：`com.ateng.ruankao.designpattern.<pattern>` 下分别构建 `standard/`（GoF 标准抽象骨架）与 `exam/`（历年机考填空真题复现与断言验证）。

3. **分阶段与批次推进策略**：
   - **第一批次（稳拿盘 26~28 分）**：优先攻坚试题一（DFD 数据流图）与试题五（Java 设计模式实战工程）；
   - **第二批次（核心分析盘 22~24 分）**：攻坚试题二（数据库 E-R 与 SQL）与试题三（UML 建模分析）；
   - **第三批次（战略防守盘 6~8 分）**：攻坚试题四（C 语言算法设计与时空复杂度分析）。

## 预期影响与权衡

- **优势**：
  - 目录边界清晰，Java 单元测试与 VitePress 文档同构演进；
  - 考点与代码双轨闭环，实现从“纸面答题”到“控制台断言”的真实技能迁移；
  - 及格目标分值设定为 $13 + 12 + 12 + 7 + 13 = 57$ 分，提供充裕的安全边际。
- **代价**：
  - 双工程（Node.js + Maven）共存需在 CI/CD 中针对不同路径执行差异化流水线，但本地执行互不干扰。
