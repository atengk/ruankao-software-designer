# 0002 面向对象与设计模式实战验证语言选型 (Java)

## 背景与上下文

软考软件设计师下午应用技术第 6 题为面向对象程序设计与设计模式填空（15分），历年试卷提供 C++ 与 Java 两种语言版本供考生二选一作答。为了在 `src/` 中构建可运行的设计模式验证工程，需要锁定唯一的官方主力语言，避免双语言维护带来的心智分散。

## 架构决策

选择 **Java (Java 21/17)** 作为软考设计模式与面向对象实操的唯一基准语言。

1. **语法纯粹性**：Java 的接口（`interface`）、抽象类（`abstract class`）、泛型与多态机制与 GoF 23 种设计模式的原生类图结构一一对应，无指针解引用、析构函数及多重继承等语法噪音。
2. **答题投产比**：历年真题中 Java 填空考查点更加聚焦在类间关系（如装饰者与被装饰者组合、观察者注册、策略传递），答题得分率通常高于 C++。
3. **工程易测性**：使用标准 Maven/JUnit 5 即可快速验证模式流转与边界条件，测试用例可读性极高。

## 预期影响与权衡

- **优势**：备考代码工程轻量清晰，完全杜绝内存泄漏排查成本，最大化强化模式识别反应。
- **代价**：对于 C++ 底层开发者需适应 Java 关键字，但软考下午题 Java 部分语法属于基础子集，转换门槛极低。
