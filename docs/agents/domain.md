# 领域文档规范

定义工程技能在探索软考软件设计师知识库时如何消费和更新领域文档。

## 探索前必读

- 根目录下的 **`CONTEXT.md`**：记录软件设计师考试大纲核心领域模型、知识体系与专业术语表。
- 根目录下的 **`CONTEXT-MAP.md`**（若存在）：指向各子上下文模型（单上下文项目通常不需要）。
- **`docs/adr/`** 目录：记录关键技术与架构决策（如备考知识框架选型、算法/模式验证实现等）。

若上述文件尚不存在，**静默继续执行**，无需阻断流程或强制提前生成。`/domain-modeling` 等技能在真正确立术语或架构决策时会按需渐进式创建。

## 目录结构

单上下文结构（适用于绝大多数项目及本项目）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-知识体系框架选型.md
│   └── 0002-UML图谱与设计模式实现规范.md
└── src/
```

## 统一专业术语

在输出专业概念（如考点归纳、重构方案、数据流图、设计模式）时，必须严格采用 `CONTEXT.md` 术语表中所定义的标准术语，严禁使用非标别名。若发现所需术语尚未收录，应提示通过 `/domain-modeling` 技能补充录入。

## 决策冲突预警

若输出的方案或考点解析与既有 ADR 决策相悖，必须显式标注说明原因并建议重审决策，严禁静默覆盖。
