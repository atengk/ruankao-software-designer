# 任务跟踪器：本地 Markdown

本项目的需求、考点任务与规范说明统一以 Markdown 文件的形式保存在 `.scratch/` 目录下。

## 约定规范

- **单功能/专题目录**：`.scratch/<功能或专题标识>/`
- **规范说明文件**：`.scratch/<功能或专题标识>/spec.md`
- **实现与任务清单**：每个任务独立存放于 `.scratch/<功能或专题标识>/issues/<序号>-<标识>.md`，序号从 `01` 开始编号，严禁合并为单个大文件
- **分诊状态**：在每个任务文件顶部以 `状态:` 行标注（状态枚举参见 `triage-labels.md`）
- **讨论与推进记录**：在文件底部 `## 推进记录` 标题下追加历史记录

## 当技能提示“发布至任务跟踪器”时

在 `.scratch/<功能或专题标识>/` 目录下新建对应文件（若目录不存在则自动创建）。

## 当技能提示“获取关联任务”时

读取指定路径的文件。通常会直接传入文件相对路径或任务编号。

## 寻路推进机制 (Wayfinding)

供 `/wayfinder` 技能使用。知识图谱与路线图文件对应多个子任务文件：

- **主图谱文件**：`.scratch/<目标主题>/map.md` —— 包含备忘笔记、已定决策与待探索迷雾
- **子任务文件**：`.scratch/<目标主题>/issues/<序号>-<标识>.md`，从 `01` 开始编号，正文包含具体问题或任务；`类型:` 行记录类别（`调研`/`原型`/`深入研讨`/`任务`）；`状态:` 行记录当前进度（`已认领`/`已解决`）
- **阻塞依赖**：顶部声明 `依赖任务: <序号>, <序号>`。当所列前置任务均为 `已解决` 时，该任务解锁
- **探索前沿**：扫描 `.scratch/<目标主题>/issues/` 中未关闭、未阻塞且未被认领的任务，按序号递增顺序优先处理
- **认领任务**：开展工作前标记 `状态: 已认领` 并保存
- **解决任务**：在 `## 解答与结论` 标题下追加成果，标记 `状态: 已解决`，并在主图谱文件 `map.md` 的已定决策中追加索引摘要与链接
